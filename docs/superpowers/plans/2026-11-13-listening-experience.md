## Общие правила

- **Язык:** Java, строки только русские (`res/values/strings.xml`).
- **Тесты:** в проекте нет Robolectric и Mockito, JVM-тесты проверяют чистую логику. Поэтому каждая функция делится на чистый класс с тестом (как `Checkpoint`, `SeekStep`, `ListeningProgress`) и тонкую привязку к Android.
- **Проверка после каждого этапа:** `.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`. Этапы, меняющие схему БД, — ещё `:app:connectedDebugAndroidTest` (`MigrationTest`).
- **Ветки:** один этап — одна ветка от `master`, слияние после приёмки на устройстве.
- **Экраны:** каждый новый элемент проверяется на телефоне, планшете (`layout-sw600dp-land`, `layout-sw720dp-land`) и ТВ (`layout-television`, управление с пульта).
- **Цвета:** только атрибуты темы и `PaletteBinder`, без жёстких цветов — иначе сломаются палитры и чёрная тема.
- **Совместимость со старыми версиями приложения не требуется** (решение владельца от 13.11.2026: считаем, что их нет, приложение новое). Форматы синхронизации и резервных копий можно расширять без оглядки на прежние сборки, умолчания настроек — менять.
- **Миграции Room всё равно пишутся** для каждой смены схемы: это дёшево и сохраняет библиотеку на уже установленных сборках.

## Этап 1. Закладки

### Поведение

- В плеере — кнопка «Закладка»: сохраняет главу и позицию, показывает плашку «Закладка добавлена · Заметка». По «Заметка» открывается поле для текста.
- В книге — список закладок: глава, время, заметка, дата. Нажатие — переход, долгое нажатие — изменить заметку или удалить (удаление с отменой).
- Кнопка в уведомлении и на экране блокировки — по настройке, выключено по умолчанию (место в уведомлении занято: таймер, назад, пауза, вперёд, выход).
- Закладки входят в резервную копию и облачную синхронизацию.

### Данные

Новая таблица `bookmark`, схема 20 → 21:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INTEGER PK | |
| `url_book` | TEXT NOT NULL, индекс | книга |
| `chapter_index` | INTEGER NOT NULL | номер главы на момент создания |
| `chapter_name` | TEXT NOT NULL | имя главы — чтобы найти её, если список глав изменился |
| `position_ms` | INTEGER NOT NULL | позиция в главе |
| `note` | TEXT | заметка |
| `created_at` | INTEGER NOT NULL | для сортировки и слияния при синхронизации |

Позиция хранится так же, как в `Checkpoint` (глава + миллисекунды). При переходе глава ищется сначала по имени, затем по номеру; если не найдена — сообщение, а не переход в чужое место.

### Файлы

- Новые: `room/BookmarkEntity`, `room/BookmarkDao`, `model/Bookmarks` (чистая логика: поиск главы, сортировка, слияние), `adapter/BookmarksAdapter`, лист `fragment/BookmarksSheet`, layout листа и строки.
- Изменить: `room/AppDatabase` (сущность, `MIGRATION_20_21`, список `MIGRATIONS`), `app/schemas/.../21.json` (создаётся сборкой), `layout/player_actions.xml` (пятая кнопка — проверить, помещается ли на узком экране; иначе кнопка в верхней строке панели), `activity/BookActivity`, `service/MediaPlayerService` (действие «закладка» для уведомления), `pojo/BackupPOJO`, `sync/Snapshot` и `sync/SyncRun`.

### Шаги

1. `Bookmarks` + `BookmarksTest`: поиск главы по имени и номеру, поведение при изменившемся списке глав, слияние двух наборов.
2. Сущность, DAO, миграция; дополнить `MigrationTest` (androidTest) переходом 20 → 21 с сохранением остальных таблиц.
3. Кнопка в плеере и плашка; список закладок в книге; переход через существующий `seekFromApp` / `select`.
4. Резервная копия: новое поле в `BackupPOJO`. Старые копии без него читаются как «закладок нет».
5. Синхронизация: новый раздел в `Snapshot` (сейчас разделы: `seq`, `books`, `fav`, `hist`, `people`, `pos`, `prefs`; `VERSION = 1`).
6. Действие в уведомлении по настройке.

### Риски

- **Новый раздел синхронизации.** Старые версии приложения не учитываются: раздел просто добавляется в `Snapshot`, `VERSION` не меняется. Снимок без раздела читается как «закладок нет».
- **Слияние закладок с двух устройств.** Одинаковая закладка (книга + глава + позиция) не должна задваиваться, удалённая — возвращаться. Ключ записи в разделе — `url|глава|позиция`, удаление хранится так же, как у остальных разделов (`Snapshot.merge` с базовым снимком).
- **Удаление книги из истории и избранного:** закладки не должны пропадать молча. Предложение: удалять их только вместе с явной очисткой данных книги.

### Приёмка

Закладка создаётся за одно нажатие во время воспроизведения; переход по ней работает после перезапуска и после обновления списка глав; закладки переживают резервную копию и появляются на втором устройстве.

## Этап 5. Новинки любимых авторов и чтецов

### Поведение

- Раз в сутки приложение проверяет первую страницу книг каждого избранного человека на каждом сайте, где известен его адрес (`FavoritePeople.Person.urlFor(Provider)`).
- Новые книги появляются в блоке «Новое у ваших авторов и чтецов» на экране «Продолжить» и отмечаются точкой у человека в избранном.
- При первой проверке человека текущие книги запоминаются как уже известные — без ложных «новинок».

### Запуск проверки

По образцу `SourceHealth.checkIfDue`: при запуске приложения, не чаще раза в сутки, только в безлимитной сети, не больше двух запросов одновременно.

Фоновых уведомлений о новинках в первой версии нет (решено 13.11.2026): только проверка при запуске и блок на экране. WorkManager не подключается.

### Данные

Новая таблица `person_book`: `person_key`, `kind`, `url_book` (уникально вместе), поля книги для карточки, `found_at`, `is_new`. Хранит и уже известные, и новые книги. При удалении человека из избранного его строки удаляются.

### Файлы

- Новые: `room/PersonBookEntity`, `room/PersonBookDao`, `model/NewReleases` (чистое сравнение «было — стало» + тест), `search/ReleaseCheck` (расписание и обход).
- Изменить: `AppDatabase` (миграция), `App` или `MainActivity` (вызов `checkIfDue`), `fragment/HomeFragment`, `adapter/FavoritePeopleAdapter` (точка).

### Риски

- **Нагрузка на сайты.** Aknigi24 уже блокировал IP за серии запросов (`open-issues.md`). Лимит: один запрос на человека и сайт в сутки, пауза между запросами к одному сайту, остановка обхода сайта после первого 429.
- **Число запросов** = люди × сайты. Ограничить проверку сайтами, включёнными для поиска, и показать в настройках выключатель.
- **Нестабильный порядок выдачи** на некоторых сайтах даст ложные новинки. Сравнивать по набору URL, а не по позиции в списке.

### Приёмка

У автора с новой книгой она появляется в блоке не позже чем через сутки; первая проверка не показывает ничего; проверка не идёт в мобильной сети.

## Этап 6. Статистика прослушивания

### Поведение

Экран «Статистика» (из бокового меню или из «Продолжить»): время за сегодня, неделю, месяц; график по дням за 30 дней; число дослушанных книг; серия дней подряд.

### Данные

Таблица `listen_day`: `day` (номер дня в местном времени, PK), `seconds`. Счётчик дослушанных книг — таблица `finished_book` (`url_book`, `finished_at`), запись при достижении 100 % по `ListeningProgress`.

Считается реальное время воспроизведения, а не пройденная позиция: час на скорости 2× — это час.

### Файлы

- Новые: `room/ListenDayEntity`, `room/ListenDayDao`, `model/ListeningStats` (чистый: накопление, граница суток, серия дней) + тест, `fragment/StatsFragment`.
- Изменить: `service/MediaPlayerService` — накапливать секунды, пока плеер действительно играет, и сбрасывать в БД там же, где пишется контрольная точка (`checkpointNow`); `AppDatabase`; `BackupPOJO`.
- График — уже подключённой `williamchart`, если она подходит для столбцов по дням; иначе простая собственная View.

### Вне первой версии

Облачная синхронизация статистики: суммы с двух устройств нельзя просто перезаписать. Потребуется ключ «день + устройство». В первой версии — только резервная копия.

### Приёмка

Час прослушивания даёт 60 ± 1 минут в статистике независимо от скорости; пауза и буферизация не считаются; переход через полночь делит время между днями.

## Этап 7. Усиление громкости

Для тихих записей: ползунок 100–200 % рядом с эквалайзером и балансом.

- Реализация — в цепочке собственных аудиопроцессоров, где уже работают `BalanceAudioProcessor` и `SkipSilenceProcessor` (подключение — в `EndAwareRenderersFactory`). Сначала проверить, что именно делает существующий «ночной звук» в `BalanceAudioProcessor`: возможно, усиление проще добавить туда.
- Обязателен мягкий ограничитель: простое умножение 16-битного звука даёт хрип на громких местах.
- Настройка хранится рядом с эквалайзером (`StorageUtil.STORAGE`).
- Громкость таймера сна (`player.setVolume` при затухании) не затрагивается: усиление работает до неё.

Тест — по образцу `BalanceAudioProcessorTest`: при 100 % выход равен входу; при 200 % тихий сигнал удваивается, громкий не выходит за пределы.

**Приёмка:** на тихой книге громкость заметно выше без искажений; затухание таймера сна работает как прежде.

## Отложено

- **targetSdk 36.** Срока нет: приложение распространяется через GitHub. Реальный объём — принудительный edge-to-edge на всех экранах (сейчас около 20 экранов на `fitsSystemWindows`), жест «назад» с предпросмотром (`MainActivity`, `BookActivity` ещё переопределяют `onBackPressed`), шестичасовой лимит сервиса загрузок. Отдельный план с проверкой каждого экрана.
- **Picasso → Glide.** Picasso работает через общий OkHttp-клиент с прокси (`App.java:375`). Сначала дать Glide тот же транспорт, затем переносить вызовы по одному экрану с проверкой обложек заблокированных сайтов.
- **Разбор `MediaPlayerService`** (3359 строк). Не отдельной задачей: этапы 1, 4, 6 и 7 сами выносят из него чистые классы (`BrowseTree`, `ListeningStats`, `SeekUndo`).
- **Единая обёртка над настройками.** Не нужна: типизированные части (`PlaybackSettings`, `SyncedSettings`) появляются там, где есть логика.
- Пункты `tasks/open-issues.md` (T09, T11, T12) — без изменений.
